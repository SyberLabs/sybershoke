# Sybershoke report: the Jev/Kev decision path

Generated by `shoke report`. Do not edit by hand: `scripts/report.sh --check` fails when this file differs from what the code produces.

## What this is, and is not

This is a **model**, written from the SyberLabs project documents. It is not the RISE Worker, and it never calls Jev or Kev. It reproduces the structure those documents describe: an 8000 ms deadline, a Kev scale-to-zero cold start of about 35000 ms, a keyword override that forces the night-drive look, a decision cache, and a menu that answers are validated against. A finding here is a finding about that structure. Whether the real Worker has the same failure needs the phase 2 adapter run against recorded fixtures.

The RISE Worker source differs from this model in ways that matter (`docs/REDTEAM.md`, R2): it makes one provider call per request, so it has no retries for `retry-storm` to break; its 8000 ms limit covers the provider call only; its cache keys on the exact intent plus a variation cohort; and it has no fallback, so `cache-fallback` cannot happen until one is added.

**The counts below are not rates.** Each is the number of seeds on which a check failed, and it is set by assumptions, not measurements: the idle time before a scale-to-zero host goes cold (120000 ms; the docs give the cold-start cost but not this threshold), the traffic (about one request in twelve follows a gap of 130 to 200 seconds, one in four repeats an earlier request), the fault windows (1 to 16 seconds), and the provider latencies. Changing one of them moves a count by up to eight times (`redteam/sensitivity.sh`). What holds whatever the assumptions: whether a bug is caught at all (a count above zero), and that a floor removes every I7 failure.

Parameters: 200 seeds (0 to 199), 60 requests per seed, 2 faults per seed drawn from every class, deadline 8000 ms, at most 2 provider calls per request.

## 1. Configurations

Each cell is the number of seeds (of 200) on which the invariant failed. `n/a` means the row does not apply the I7 policy. I7 is a policy, not a bug: it asks that every request be answered with a plan even when the provider fails, which needs a preset floor.

Read the `kev scale-to-zero` I7 count as a demonstration of the mechanism, not a failure rate. It is driven by the *assumed* traffic: a request that arrives after a long idle gap and misses the cache meets a 35000 ms cold start against an 8000 ms deadline, so nearly every seed contains one. Real traffic decides how often that happens. The `with floor` row shows the floor removes it entirely, which holds whatever the traffic.

## 2. Seeded bugs and their smallest reproductions

Each bug removes one safeguard, and none of them labels its own mistakes: a cached fallback is stored as an ordinary entry. The shrinker takes the first failing seed, removes faults, then trims each surviving window from either end and moves it earlier, until the invariant stops failing. It keeps the invariant failing, not necessarily the same request. A window longer than 250 ms had to cover several calls.
